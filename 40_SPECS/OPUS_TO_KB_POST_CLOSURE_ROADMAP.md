# OPUS → KB POST-CLOSURE ROADMAP

## Decision
After OPUS/OWASYS technical closure, the sequence is:
1. finalize OPUS documentation / RefBook;
2. produce and validate an OPUS demonstration application generated through OWASYS, without manual repair of the generated application;
3. resume KB as an OPUS application generated by OWASYS.

## KB generation contract
KB MUST originate from the normal OWASYS → secured REST → owasys-back → allow-listed Composer → OPUS generation path. KB is not a hand-built exception to OPUS.

## LSSTAR decision
LSSTAR is optional for KB. It MAY be enabled as an application capability when its services are useful, but:
- OPUS generation MUST NOT require LSSTAR;
- OWASYS MUST NOT hard-code LSSTAR into generic site generation;
- KB core MUST remain operational without LSSTAR;
- LSSTAR integration, when selected, MUST be isolated behind an explicit OPUS application module/service contract.

## Gate before KB restart
KB restarts only after the OPUS documentation and generated-demo acceptance gates are closed.
