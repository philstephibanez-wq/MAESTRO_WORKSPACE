R8B7L is a cumulative successor to the uncommitted R8B7K presentation experiment and replaces the complete registry SCORE template.

## Problem

The Applications view visually separated OWASYS core from generated applications in a way that made the relationship unclear. It also rendered diagnostic/audit cards and singleton compliance pills that cluttered the operational Applications view.

## Required presentation

- OWASYS is the system container.
- `owasys-front` and `owasys-back` are the two OWASYS core applications and must render next to each other in the first application row.
- Applications generated by OWASYS render in a second row inside the same OWASYS Applications card, preserving a clear visual relationship without presenting them as OWASYS core components.
- Generated applications remain selectable and deletable according to the existing ACL/view contract.
- Create and clear-current-context actions remain available.
- Discovery audit, singleton audit, runtime SQLite and recent-event panels are removed from the Applications operational view.
- Singleton compliance pills are removed from application cards on this view.
- No backend, REST, FSM, registry persistence, ACL or source-model behavior changes.
- No application ID such as `essai` is hardcoded.

## Scope

One complete changed file only:

`sites/owasys-front/application/registry/templates/index.score`

The view keeps the existing registry projection rule already exposed to SCORE: system/non-generated entries are `not entry.deletable`; generated Composer applications are `entry.deletable`.

## Acceptance

- SCORE condition/loop blocks balanced.
- Existing create, clear-context, select and delete form contracts preserved.
- `owasys-front` and `owasys-back` appear side by side at desktop width.
- Generated applications appear below them in the same OWASYS card.
- Removed diagnostic panels do not appear on `/applications`.
- No runtime regression in application selection, creation entry point or deletion form.
